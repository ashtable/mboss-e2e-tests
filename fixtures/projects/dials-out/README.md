# `dials-out`

Not a whole project. This is an overlay
`extensionProject()` lays over a freshly scaffolded
one, and it holds a graph whose transaction block is
followed by a code-behind with two handlers that
reach another system and one that does not.

All three handlers have the same signature on
purpose. A row leaves the picker's list for the
first thing wrong with it, so a fixture whose
dialling handler also took the wrong type would
prove nothing about which rule put it away. Alike in
everything the rules look at except what they do,
the only thing that can move `chargeCard` from
offered to hidden is the block it is aimed at.

`wireSettlement` reaches outward too, and the
difference between it and `chargeCard` is one of
spelling: it builds its socket on the line that
dials, so its call hangs off no name in the file.
The two are here together because for a while the
packaged extension told a person different things
about them — the one was greyed and the other
offered, on a rule that is supposed to be about
what a handler does rather than how it was
written.

The graph runs the way the product says it should:
the card is charged in a step, where the call is
checkpointed and retried on the step's terms, and
the claim is marked settled in a transaction, where
the write lands with the run's checkpoint. Nothing
on screen is wrong on purpose — the refusal this
fixture exists for is one the spec has to go and ask
for.
